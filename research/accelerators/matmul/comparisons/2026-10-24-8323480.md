## What differs

- **ISA vs fixed function.** VCPU-8 is a programmable 8-bit CPU running a generated program (loops, address arithmetic, branches); the accelerator is fixed-function hardware for exactly this operation. The CPU cycles include all of the program’s control overhead.
- **Numeric format.** VCPU-8’s MUL is unsigned 8 × 8 and keeps only the low byte of the product, so the program forms each signed 16-bit product by shift-and-add (one loop pass per multiplier bit up to its highest set bit, eight for a negative multiplier) and corrects for a negative multiplier. The accelerator’s processing element multiplies signed INT8 directly. The CPU’s cycles therefore depend on the operand values; the accelerator’s do not.
- **INT32 accumulation.** The CPU keeps each INT32 accumulator as 4 bytes in memory and adds the sign-extended product byte by byte, rippling the carry with branches because the ISA has no add-with-carry. The accelerator has a 32-bit adder per processing element. Both wrap on overflow like the reference.
- **Memory.** VCPU-8 has 256 bytes for code, data and stack together, so only products up to 4 × 4 × 4 fit (unsupported workloads list their byte counts). The accelerator has separate on-chip buffers (A and B 64 × 64 INT8 elements each, banked one bank per array row or column, C 64 × 64 INT32) behind a simplified testbench host port, and its totals include the transfers through that port.
- **No clock frequency.** Cycles are clocks, not time. The two designs would not run at the same clock, and no clock frequency is assumed for either, so no time, throughput per second or speed-up is reported. The synthesis baselines record Fmax estimates for named FPGAs; converting cycles with them later would give labelled estimates, and this report does not do it.
- **No power.** Power was not measured for either design, so the report makes no energy or efficiency claim.
- **Memory accesses.** The two access counts measure different things: the CPU’s are every data-memory read and write of the program (operands, the accumulator read-modify-write, the cptr variable and the one PUSH/POP), the accelerator’s are host-port transfers only.
- **Resources.** The generic Yosys flows differ: the CPU baseline maps its 256-byte memory to flip-flops (2048 of its flip-flops), while the accelerator baseline keeps its buffers as memory cells outside the cell count. The ECP5 rows (both designs’ memories in block RAM, multipliers in DSP blocks) are the closest like-for-like resource comparison.
