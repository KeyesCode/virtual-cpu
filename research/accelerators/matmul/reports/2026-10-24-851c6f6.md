# Matmul accelerator benchmark

Result: **PASS**, the correctness gate passed for all 27 cases: every C matched `@vcpu/accelerator-reference` element by element before any number was recorded.

Revision `matmul-os-r1`, commit `851c6f6`, created 2026-10-24T09:08:02.052Z; toolchain: OSS CAD Suite 2026-10-16. Arrays 4x4, 8x8, 16x16; workloads are M × K × N (A is M × K, B is K × N, C is M × N), operands from the `random` generator with seed 1.

- One MAC is one multiply plus one accumulate: a signed INT8 × INT8 product added into a signed INT32 accumulator. A workload of M × K by K × N is M · N · K MACs. Ops count each MAC as two operations (ops = 2 × MACs).
- Cycles: rising clock edges of the Verilated matmul_top, counted by the Verilator runner (tb/sim/matmul_sim.cpp). They are clocks, not time: no clock frequency is assumed, so no time or throughput per second is reported.
- Transfer in and transfer out: the simplified testbench host port (A and B written in parallel, one element per port per clock; C read one element per clock). It is a testbench convenience, not a production memory system.
- PE utilization = MACs / (ROWS · COLS · compute cycles): the fraction of PE-clocks of the compute phase (PREPARE_TILE, COMPUTE and DRAIN of every tile) that did a useful MAC. STORE, transfer and handshake clocks are not in the denominator.

Formulas: `macs = M · N · K`; `tiles = ⌈M / ROWS⌉ · ⌈N / COLS⌉`; `utilization = macs / (ROWS · COLS · compute)`; `macsPerCycleCompute = macs / compute`; `macsPerCycleTotal = macs / total`; `opsPerCycleCompute = 2 · macs / compute`; `opsPerCycleTotal = 2 · macs / total`; `fillDrain = compute − tiles · K (the PREPARE_TILE and DRAIN clocks)`; `bytesIn = M · K + K · N (INT8 operands)`; `bytesOut = 4 · M · N (INT32 results)`.
